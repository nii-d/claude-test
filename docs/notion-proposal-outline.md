## S7. 課題A：案件管理 ― 何が起きているか

**（1）規模の実態**

```
        ┌─ 営業 1〜2名
        ├─ 運営管理 1〜2名
1案件 ──┼─ 講師管理 1名          ＋ 機材部門
        ├─ 講師 1〜2名           ＋ コンテンツ作成部門
        └─ PMO 1名（新設）
```

- 1案件あたり **のべ6〜8名** が関与し、**年間約700件**

**（2）現に起きたこと**

| 起きたこと | 失われたもの |
|---|---|
| チャットでの依頼を運営担当が見逃し、期日が守られなかった | 納期 |
| 教材開発の成果物が、期日になっても出てこない（部門間の温度感の差） | 納期・部門間の信頼 |
| 講師選定が遅れ、機材準備が間に合わなかった | 実施品質・顧客信用 |

**（3）なぜ起きるのか — 構造の問題**

| # | 欠陥 | 内容 |
|---|---|---|
| A-1 | 可視性がない | グループチャットは招待された人しか見られない。招待漏れ＝情報から遮断 |
| A-2 | 横断して見えない | Excelが各自バラバラ。案件間の比較も全体の集計も不可能 |
| A-3 | 管理手法がない | WBS・ガントが標準装備でなく、進捗と依存関係を追えない |

> **⚠ 作成時の注意**
> **部署名・個人名は絶対に書かない**。「担当者が見逃した」ではなく「見逃せてしまう仕組みだった」と、必ず主語を仕組みに置くこと。この資料は社内に回覧されるため、ここを誤ると導入後に協力を得られなくなる。

## S8. 課題B：会議と議事録 ― 何が起きているか

**メッセージ**: 目的が曖昧な会議に、年間 **約7,300万円** 相当の人件費が投じられています。

**（1）会議のコスト（階層別）**

| 階層 | 人数 | 週の会議時間 | 年間コスト |
|---|---|---|---|
| MG以上 | ◯名 | 週22時間（仮） | ◯,◯◯◯万円 |
| リーダー | ◯名 | 週17.5時間（実測: 15〜20時間） | ◯,◯◯◯万円 |
| 一般社員 | ◯名 | 週5時間（仮・要確認） | ◯,◯◯◯万円 |
| **合計** | **140名** | | **約2億円** |
| うち目的が曖昧なもの（35%） | | | **約7,300万円** |

計算式: 人数 × 週の会議時間 × 45週 × 時間単価3,000円
時間単価: 平均年収450万円 × 1.25（法定福利費等） ÷ 1,900時間 ≒ 3,000円

**（2）議事録の現状 — 情報が5か所を経由している**

```
Teams会議 → 文字起こし → AIで議事録生成 → Word化 → OneDriveに保存 → リンクをTeamsで共有
                                          └→ OneNoteにコピペ → リンクをTeamsで共有
```

- 保存先が人によって違い、**どこに何があるか分からない**
- チャットに流れたリンクは、時間が経てば遡れない
- **議事録は残っているのに、決定事項が追えない**

**（3）なぜ起きるのか — 構造の問題**

| # | 欠陥 | 内容 |
|---|---|---|
| B-1 | 目的が事前に定義されない | アジェンダを作る型がないため、「とりあえず集まる」定例が生き残る |
| B-2 | 決定が構造化されない | 決定事項・担当・期日が文章の中に埋もれ、検索も集計もできない |
| B-3 | 置き場所が分散する | Word / OneDrive / OneNote / Teams をまたぐたびに情報が流れていく |

> **⚠ この試算の扱い（重要）**
>
> **① 一般社員の会議時間が未確認。** 実測されているのはリーダークラス（週15〜20時間）のみ。一般社員を週5時間と仮置きしているが、ここが動くと総額が大きく動く。**Viva Insights またはTeams利用状況レポートで階層別の実測を取ること。** 情シスに依頼すれば出せる可能性が高い。
>
> **② 人数の内訳も仮置き。** 上表はMG以上20名／リーダー40名／一般80名で計算した例。実際の構成比で置き換えること。
>
> **③ 時間単価は平均年収ベースのため、MG層については過小評価になっている。** これは「控えめに見せる」意図なので、そのままでよい。質問されたら「意図的に低く見積もっています」と答える。
>
> **④「では人を減らせるのか」と聞かれる。** 答えは「削減した時間は案件対応と提案活動に回します」。**人件費が浮くとは絶対に言わないこと。** 言えば人員削減の話にすり替わり、現場の協力を失う。

## S9. Notionによる解決 ★重要スライド

**S6と同じ左右2カラムで、Before / After を並べる**

### 課題A：案件管理

| | Before | After |
|---|---|---|
| A-1 可視性 | 招待された人しか見えない | 全案件が誰からも見える |
| A-2 横断性 | Excelがバラバラで集計不能 | 全案件が同じ型。**PMOが1画面で700件を俯瞰** |
| A-3 管理手法 | 進捗と依存関係が追えない | ステータス・担当・期日が構造化され、遅延案件が自動で浮かび上がる |

### 課題B：会議と議事録

| | Before | After |
|---|---|---|
| B-1 目的 | とりあえず集まる定例が残る | **アジェンダを事前に書くことが型になる**。書けない会議は開かれなくなる |
| B-2 決定 | 文章に埋もれて追えない | 決定事項・担当・期日が項目として残り、検索・集計できる |
| B-3 置き場所 | Word/OneDrive/OneNote/Teamsに分散 | すべてNotionの1か所。案件からも人からも辿れる |

**話法メモ**: **B-1の「書けない会議は開かれなくなる」が、この提案の思想を最もよく表す一言。** ツールが会議を減らすのではなく、アジェンダを書くという行為が目的のない会議を自然に淘汰する。ここは口頭で強調する。

## S10. そして、この2つは1つの仕組みで繋がります

```
  会議前            会議中・会議後              自動的に現れる場所
┌──────────┐      ┌──────────────┐      ┌────────────────────┐
│ アジェンダを │ ───→ │ 議事録を書く   │ ───→ │ ① 案件ページ        │
│ 事前に作る   │      │ 決定事項・ToDo │      │ ② 担当者のToDo一覧  │
│（課題B の解決）│      │ を項目として   │      │ ③ PMOの全案件ビュー │
└──────────┘      │ 登録する       │      └────────────────────┘
                    └──────────────┘         （課題A の解決）
                                              ※ すべて同じ実体
```

- 会議で決まったToDoは、**転記せずにそのまま案件のタスクになる**
- **二重入力が発生しない**

**話法メモ**: S6で「2つの課題」と宣言し、S9で「それぞれ解決する」と示した上で、ここで初めて「実は1つの仕組みだった」と繋げる。**順番が重要**——最初から統合して語ると、聞き手はどちらの課題の話かを見失う。

## S12. Microsoft 365 では足りないのか

**メッセージ**: 検討した結果、一部はM365で対応します。残りが今回のご相談です。

| やりたいこと | M365での解 | 判断 |
|---|---|---|
| チャットの可視化 | Teamsのパブリックチーム／チャネル | ✅ **Notionは不要。この方針で実施します** |
| タスク・WBS・ガント（課題A） | Planner（上位機能は追加ライセンス） | △ 案件情報・議事録とは別の場所に持つことになる |
| ストック情報・議事録（課題B） | Loop / SharePoint / OneNote | △ 文書であってデータではない。集計・横断が困難 |
| 案件の一覧・台帳（課題A） | Lists | △ 議事録・ドキュメントと連動しない |

**結論**: すべてを満たそうとすると **Planner + Lists + Loop + SharePoint の併用**になる。

- 同じ情報を複数箇所に入力する **二重管理コスト**が発生する
- どれが最新かがわからなくなり、**結局チャットで聞くことになる**（＝現状に戻る）
- **いま解決したい「分散」を、別の形で作り直すことになる**

**役割分担の明示**:

> **Microsoft 365 = 保管・伝達 / Notion = 構造化された実行管理**
> Microsoft 365 は継続利用し、置き換えません。

> **⚠ 数字の裏取り**
> Plannerの上位機能（ガント・依存関係）が追加ライセンスを要するかは、**提出前に必ず最新のライセンス体系を確認すること**。

**話法メモ**: 「M365で済む部分は済ませます」と正直に認めている点がこのスライドの価値。全否定すると「Notionを売り込みたいだけ」に見える。

## S13. Notionでなければならない一点

**メッセージ**: 議事録が「文書」ではなく「データ」であること。これが決定的な差です。

| | 議事録の正体 | 結果 |
|---|---|---|
| Word / OneNote / Loop | **文書**。決定事項もToDoも、文中に埋まった「文字」 | 転記しないと管理に使えない。転記されなければ消える |
| Notion | **データベースのレコード**。ToDoは案件に紐づいたタスクそのもの | 議事録を書いた時点で、管理の入力が完了している |

- 「ドキュメントを書く機能」と「データベース機能」が**同じ製品の中で繋がっている**こと
- 案件 ⇔ 議事録 ⇔ タスクの**リレーション**と、**立場別のビュー**（営業／運営／講師管理／PMO）が1つの実体の上に成立する
- これがS10の仕組みを成立させる唯一の条件

**話法メモ**: 「一元化したい」だけでは理由にならない（「OneNoteに一元化すればタダ」と返される）。**「文書ではなくデータになる」という一点に絞る**ことで、初めて他ツールとの差が説明できる。第2部の中核。

## S14. 他のツールとの比較

**メッセージ**: 専用のプロジェクト管理ツールも検討しましたが、今回の要件には合いません。

| 評価軸 | Microsoft 365 | 専用PM管理ツール<br>（Asana / monday.com 等） | **Notion** |
|---|---|---|---|
| 案件管理（課題A） | △ Plannerで一部 | ◎ 得意領域 | ○ 実務水準を満たす |
| 議事録との統合（課題B） | △ 別アプリになる | △ ドキュメント機能が弱い | ◎ 同一製品内で連結 |
| ナレッジ蓄積 | ○ SharePoint | △ 不得意 | ◎ 得意領域 |
| 全社員が使えるか | ◎ 既に全員が保有 | △ 管理者向けの設計が多い | ○ 学習容易 |
| 課題A・Bを1つで満たすか | ✕ | ✕ | **◎** |

**結論**: 専用PMツールは案件管理単体では優れているが、**議事録・ナレッジと分離するため、課題Bが解決しない**。課題AとBを1つの基盤で解くという要件を満たすのはNotionのみ。

**話法メモ**: 「Notionが全部で一番」とは言わない。**個別項目では他ツールが勝る点を正直に認めた上で、「2つの課題を1つで解く」という要件で選んでいる**と説明する。この誠実さが説得力になる。

# 別添C: 数字の作り方（試算シート）

## C-1. 時間単価の算出

```
時間単価 = 平均年収 × 1.25（法定福利費等） ÷ 年間労働時間
        = 450万円 × 1.25 ÷ 1,900時間
        ≈ 2,960円 → 3,000円/時 として計算
```

※ 年収レンジは350万〜900万と幅がある。**平均値で計算していることを注記する**。MG層のコストは過小評価になるが、控えめに見せるため平均値を使う。

## C-2. 会議コスト（課題B）

```
階層別に算出し合算する:

  MG以上   ： ◯名 × 週22時間（仮）    × 45週 × 3,000円
  リーダー ： ◯名 × 週17.5時間（実測） × 45週 × 3,000円
  一般社員 ： ◯名 × 週5時間（仮）      × 45週 × 3,000円

  目的曖昧分 = 合計 × 35%（体感3〜4割の中央値）
  削減見込み = 目的曖昧分 × 30%（控えめに設定）
```

**計算例**（MG以上20名／リーダー40名／一般80名と仮置きした場合）

| 階層 | 人数 | 週時間 | 年間コスト |
|---|---|---|---|
| MG以上 | 20名 | 22時間 | 5,940万円 |
| リーダー | 40名 | 17.5時間 | 9,450万円 |
| 一般社員 | 80名 | 5時間 | 5,400万円 |
| **合計** | **140名** | | **2億790万円** |
| 目的曖昧分（35%） | | | **7,276万円** |
| 削減見込み（その30%） | | | **2,183万円** |

> **⚠ この計算例の前提**
> - **人数の内訳は仮置き。** 実際の階層別人数で置き換えること
> - **一般社員の週5時間は根拠のない仮定。** 実測されているのはリーダークラス（15〜20時間）のみ。ここが動くと総額が大きく動く
> - MG以上の「週22時間」も「リーダーより多い」からの推定
> - **Viva Insights / Teams利用状況レポートで階層別の実測を取ること**

## C-3. 手戻り・遅延コスト（課題A）

```
年間損失 = 700件 × 遅延・手戻り発生率◯% × 1件あたり追加工数◯時間 × 3,000円
```

**⚠ 発生率と追加工数は実測が必要。** 過去半年の案件から数件をサンプル調査するのが現実的。**数字を作れない場合は、金額換算せずS7の実例による定性説明にとどめる**（無理な数字は突かれる）。
