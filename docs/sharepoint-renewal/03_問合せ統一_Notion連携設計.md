# 問合せ導線の統一と Forms → Notion 連携設計

## 1. 現状の問題の整理

| 現象 | 本質的な問題 |
|---|---|
| サービス開発部門は Teams チャネル、他部署は Forms | **入口の形式がバラバラ**＝依頼者が「どこに言えばいいか」を毎回考える |
| Forms しか無い部署がある | **依頼後が見えない**＝投げたら音信不通。催促が個人チャットに流れる |
| 部署ごとに Forms が別 | **集計できない**＝どの部署にどれだけ依頼が溜まっているか誰も知らない |

→ 直すべきは「Forms を全部署に配ること」ではなく、**入口を1つにし、依頼後の状態を全社員に見せること**です。

---

## 2. 導線の統一ルール（全社共通・これだけ覚えてもらう）

| 用件 | 行き先 |
|---|---|
| ① まず調べたい（制度・手順・様式） | **knowledge / 正本置き場**（各部サイトの FAQ） |
| ② ちょっと聞きたい・相談したい（作業は発生しない） | **Teams の該当部署チャネル** |
| ③ 作業をお願いしたい（正式依頼） | **全社依頼 Forms** |

**「Teams で相談 → 作業が発生すると分かった時点で Forms」** が基本動線です。
Teams チャネルは廃止しません（相談の敷居を上げると、結局個人チャットに戻る）。ただし **チャネルで受けた依頼も、担当者が Forms に代理起票する**か、Notion にカードを起こすルールにします。ここを徹底しないと今と同じになります。

### 各部サイトTOPの「問合せブロック」（全部署で同一レイアウト）

クイックリンク Web パーツで、**必ずこの4つを、この順で**置く。

```
[ ➊ この部署に依頼する（Forms） ]  [ ➋ 相談する（Teams チャネル） ]
[ ➌ よくある質問（FAQ）         ]  [ ➍ 依頼の進捗を見る（Notion） ]
```

課ごとに分ける場合は ➊ を課の数だけ並べる（Forms の**事前入力リンク**で「宛先部署／宛先課」を選択済みにしたURLを使う）。

さらにホームに **標準リードタイム表** を必ず記載します。

| 依頼種別 | 一次回答 | 完了目安 |
|---|---|---|
| 問合せ・確認 | 1営業日 | 3営業日 |
| 資料作成・データ抽出 | 1営業日 | 5営業日 |
| システム改修・開発 | 2営業日 | 都度見積 |

## 3. Forms は「全社1本＋分岐」にする

### 部署ごとに作らない理由

| | 部署ごとに7本 | 全社1本＋分岐（**推奨**） |
|---|---|---|
| 依頼者の迷い | 「これはどの部署？」で止まる | 1本目の設問で選ぶだけ |
| 集計 | 7つの回答セットがバラバラ | 1つに集約。部署別は列でフィルタ |
| Power Automate | **7本を個別に保守** | 1本 |
| Notion DB | 7つに割れるか、7本のフローで1つに寄せる | 1つ |
| 部署の増減（組織改編） | フローとDBを作り直し | **選択肢を1行足すだけ** |

組織改編を控えている以上、7本構成は再構築のたびに作り直しになります。

### Forms の設問設計

| # | 設問 | 種類 | 備考 |
|---|---|---|---|
| 1 | 宛先部署 | 選択（必須） | 分岐の起点 |
| 2 | 宛先課 | 選択（必須） | 部署選択に応じたセクションへ分岐 |
| 3 | 依頼種別 | 選択（必須） | 問合せ／資料作成／データ抽出／システム改修／その他。**部署ごとに選択肢を変える** |
| 4 | 件名 | 短文（必須） | Notion のページタイトルになる。「40字以内で」と注記 |
| 5 | 依頼内容 | 長文（必須） | プレースホルダに記入例を入れる |
| 6 | 背景・目的 | 長文 | **これを必須にすると手戻りが激減します** |
| 7 | 希望納期 | 日付（必須） | |
| 8 | 緊急度 | 選択（必須） | 通常／急ぎ（理由必須）／至急（上長承認済み） |
| 9 | 関連ファイル | ファイルアップロード | |
| 10 | 全社公開してよいか | 選択（必須） | **公開／非公開（人事・労務・個人情報を含む）** |

**設問10 は必ず入れてください。** 「全社員が見れる」要件と、人事・労務・経理の個人案件は両立しません。非公開の依頼は Notion の別DB（管理部限定）に振り分けます。

### Forms 作成上の注意
- **必ずグループ（Microsoft 365 グループ）所有の Forms** として作成する。個人所有だと作成者の退職時に消えます。所有グループは管理部の M365 グループを推奨。
- 「回答者の名前を記録する」を有効化（組織内限定）→ 依頼者を自動取得。
- 添付ファイルはグループ所有サイトに保存されるので、**全社員が閲覧できるサイト**を所有グループにするか、Power Automate で全社閲覧可のライブラリへコピーする。

## 4. Forms → Notion 連携（Power Automate）

### 4.1 Notion タスクDB の設計

DB名: **依頼・タスク管理**

| プロパティ | 型 | 設定元 | 用途 |
|---|---|---|---|
| 件名 | タイトル | Forms Q4 | |
| 依頼ID | テキスト | フローで採番 `REQ-YYYYMMDD-nnn` | 問合せ時の識別子 |
| 依頼者 | テキスト（またはPerson） | Forms 回答者 | |
| 依頼元部署 | セレクト | Entra から補完（またはFormsで選択） | |
| **宛先部署** | セレクト | Forms Q1 | ビューの主軸 |
| **宛先課** | セレクト | Forms Q2 | |
| 依頼種別 | セレクト | Forms Q3 | |
| 依頼内容 | テキスト | Forms Q5 | ページ本文にも展開 |
| 背景・目的 | テキスト | Forms Q6 | |
| 緊急度 | セレクト | Forms Q8 | |
| **希望納期** | 日付 | Forms Q7 | |
| **約束納期** | 日付 | 受付側が入力 | 希望と約束を分けるのが重要 |
| **ステータス** | ステータス | 既定「未受付」 | 未受付／受付済／対応中／確認待ち（依頼者）／完了／差戻し／対象外 |
| **担当者** | Person | 受付側が入力 | |
| 受付日 | 作成日時 | 自動 | |
| 一次回答期限 | 日付 | フローで算出（受付日＋1営業日） | |
| 完了日 | 日付 | 完了時に入力 | |
| 期限超過 | 数式 | `約束納期 < today() and ステータス != 完了` | 赤表示 |
| 添付 | URL | SharePoint リンク | |
| 関連リンク | URL | SharePoint / Teams | |
| 公開区分 | セレクト | Forms Q10 | 公開／非公開 |

> **営業日計算は Notion の数式では扱いづらい**ので、`一次回答期限` は Power Automate 側（`addDays` ＋ 土日祝スキップ）で計算して書き込むほうが確実です。

### 4.2 ビュー（全社員が見る前提）

| ビュー | 内容 | 想定利用者 |
|---|---|---|
| 全社ボード | ステータス別カンバン（宛先部署でグループ化） | 全社員 |
| 部署別 | フィルタ: 宛先部署 = 自部署 | 受付部署 |
| 自分の依頼 | フィルタ: 依頼者 = me | 依頼者 |
| 期限超過 | フィルタ: 期限超過 = true | 全社員・マネジメント |
| 今週完了 | フィルタ: 完了日 = 今週 | 全社員 |

**`公開区分 = 非公開` は全ビューから除外**し、管理部限定のDBまたは限定ビューで扱う。

### 4.3 Power Automate フロー

**フロー1: 依頼受付（Forms → Notion）**

```
1. トリガー : Microsoft Forms「新しい応答が送信されるとき」
2. アクション: Forms「応答の詳細を取得する」
3. アクション: Office 365 ユーザー「プロフィールの取得」（依頼者の部署を補完）
4. 条件     : Q10「全社公開してよいか」
   ├ 公開   → Notion「データベースにページを作成」（依頼・タスク管理DB）
   └ 非公開 → Notion「データベースにページを作成」（管理部限定DB）
5. アクション: 添付ファイルを全社閲覧可ライブラリへコピー、共有リンクを取得
6. アクション: Notion ページに添付リンクを更新
7. アクション: Teams「チャネルにメッセージを投稿」
              → 宛先部署のチャネルへ「新規依頼 [依頼ID] 件名 / 希望納期 / リンク」
8. アクション: Teams「ユーザーにメッセージを投稿」
              → 依頼者へ「受け付けました。[依頼ID] 進捗はこちら（Notionリンク）」
```

**フロー2: 完了通知（Notion → Teams）**

```
1. トリガー : Notion「ページが更新されたとき」（ステータス変更）
2. 条件     : ステータス = 完了 または 確認待ち
3. アクション: Teams で依頼者にメッセージ
```

**フロー3: 期限督促（スケジュール）**

```
1. トリガー : 繰り返し（毎営業日 9:00）
2. アクション: Notion「データベースにクエリ」→ 一次回答期限超過 かつ ステータス=未受付
3. アクション: 宛先部署の Teams チャネルへ督促を投稿
```

### 4.4 実装上の注意点（ここでつまずきます）

1. **Notion コネクタはプレミアム**です。Power Automate Premium（ユーザーごと or フローごと）のライセンスが必要。フロー単位ライセンス（フローごとのプラン）を3本分買うのが現実的です。**先にライセンスを確認してください。**
2. **Notion 側の設定**: Notion で「インテグレーション」を作成し、対象DBに **Connections から明示的に接続**しないと API から見えません（作っただけでは動きません）。
3. **トークンの扱い**: Notion のインテグレーショントークンは Power Automate の「接続」として保存する。フローの変数やドキュメントに**平文で書かない**。
4. **Notion の SharePoint 埋め込みは不可**: Notion は iframe 埋め込みを制限しているため、SharePoint の埋め込み Web パーツで進捗ボードを表示することはできません。**リンクボタンで運用**してください（ここは諦めが必要です）。
5. **Forms の分岐は「セクション分岐」**で作る。設問が増えると保守が重くなるので、部署固有の設問は最大3問までに抑える。
6. **Notion のゲスト/メンバー**: 「全社員が見れる」には全社員が Notion のメンバー（またはゲスト）である必要があります。**Notion のライセンス費用が人数分かかります。**社外秘情報が入るため、Notion の「Web で公開」は使えません。

## 5. 代替案（P4 / P5 が満たせない場合）

### 代替案A: Notion ライセンスが全社員分ない場合 → SharePoint リスト＋Power BI

```
Forms → Power Automate（標準コネクタ・追加ライセンス不要）
     → SharePoint リスト「依頼・タスク管理」（WorkBase サイト）
     → リストビュー（全社員 閲覧）で公開
     → Power BI で部署別の滞留・リードタイムを可視化
```

- **長所**: 追加費用ゼロ／SharePoint に埋め込める（リスト Web パーツ）／権限を Entra グループでそのまま制御できる／Teams のタブにも貼れる
- **短所**: Notion ほど柔軟でない、リレーションが弱い
- **判断**: 「全社員が見れる」ことが最優先なら、**この案のほうが要件を素直に満たします。** Notion 案は「Notion を全社基盤にする」という別の意思決定を伴います。

### 代替案B: Notion を使うが Premium が無い場合
- Notion 側の **Forms 機能**（Notion Forms）を使い、Forms そのものを Notion にする。SharePoint TOP からはリンクで飛ばす。
- 短所: Microsoft 365 のサインイン情報が取れない（依頼者を自分で入力してもらう）、添付が SharePoint に残らない。

## 6. 導入の順序（いきなり全部やらない）

| Step | 内容 | 期間目安 |
|---|---|---|
| 1 | 導線ルール（3つの行き先）を決めて全社周知 | 1週 |
| 2 | 全社依頼 Forms を1本作る（分岐は最小） | 1週 |
| 3 | **1部署だけ**でパイロット（推奨: デジタル開発部） | 2〜4週 |
| 4 | Notion or SharePoint リストへの自動連携を実装 | 2週 |
| 5 | 全部署展開、各サイトTOPに問合せブロック設置 | 2週 |
| 6 | 1か月後に依頼データを見て、FAQ とリードタイムを更新 | 継続 |

**Step 3 のパイロットを飛ばさないでください。** 設問設計は必ず1回作り直しになります。全社展開後に設問を変えると、それ以前のデータと繋がらなくなります。

## 7. 成功の測り方

四半期ごとに Notion / リストから確認する。

- 依頼件数（部署別・種別別）
- 一次回答リードタイムの中央値（目標: 1営業日以内 90%）
- 完了リードタイムの中央値
- 期限超過件数
- Forms 経由の割合（＝個人チャット依頼が減っているか。**これが本丸の指標**）
- FAQ で解決した割合（依頼件数の減少）
