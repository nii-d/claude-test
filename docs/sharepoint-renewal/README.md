# 全社SharePoint 再構築

組織改編にともなう全社 SharePoint の再構築と、問合せ導線の統一 / Notion タスク管理の設計一式。

## 成果物: 全社マニュアル（Notion インポート用）

**`notion/全社SharePointマニュアル_Notionインポート用.zip`** が本体です。
Notion の「インポート → Markdown & CSV」に投入すると、親ページ＋子ページの階層がそのまま作られます。

手順は [notion/インポート手順.md](notion/インポート手順.md) を参照してください。

### 収録内容

| 区分 | ページ |
|---|---|
| 親ページ | 全社SharePointマニュアル（要点・読者別導線・目次） |
| A. 全社員向け | A1 はじめに / A2 情報の置き場所ルール / A3 サイト一覧の見方 / **A4 各サイトの詳細（11サイト）** / A5 ファイルの扱い方 / A6 依頼と問合せのしかた |
| B. 構築・運用向け | B1 サイトアーキテクチャ設計 / B2 権限とグループ設計 / B3 依頼受付の仕組み / B4 移行計画 / B5 決めること一覧 |
| データベース | サイト一覧_DB.csv（11行）/ 依頼タスクDB_テンプレート.csv |

A4 配下の11サイトは、**全ページが同じ7項目**で記述されています。

1. 何のための場所か / 2. 責任と読者 / 3. **書かれていること** / 4. **置かれているもの** /
5. **置かないもの** / 6. 問合せ窓口 / 7. 更新ルール

## 設計の要点

1. **サブサイトではなくハブサイト＋独立サイト** — 組織改編でサイトを付け替えられるようにするため
2. **公開/非公開は「ページ」ではなくドキュメントライブラリで分ける** — ページに権限で守る力はないため
3. **URLに部署名を入れない** — 部署名が変わってもリンクが切れないようにするため
4. **権限はすべて動的グループ経由** — 改編時は人事データの更新だけで追随するため
5. **依頼は SharePoint の問い合わせボタン → Notion Form → Notion DB** — 連携部品がゼロで壊れないため

## 前提と限界

- 既存 SharePoint を直接参照していないため、本資料は**新構成における各サイトの定義**であり、既存実態の棚卸し結果ではありません。各部の確認が必要です。
- 課の名称はすべて仮です。新組織の確定後に修正してください。
- 置いている前提（ライセンス・Entra 属性など）は `B5 決めること一覧` に一覧化しています。
