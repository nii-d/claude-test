# B5 決めること一覧

**誰向け**: 経営層、管理部、デジタル開発部
**所要時間**: 5分
**この章の結論**: 最優先は「新組織の課の確定」。これが決まらないと権限グループもライブラリ構成も確定しない。

---

## 優先度順

| # | 論点 | 未決だと困ること | 提案 | 優先度 |
|---|---|---|---|---|
| 1 | **新組織の課の正式名称と数** | 権限グループ・ライブラリ数・課ページが確定しない | 最優先で確定 | **最高** |
| 2 | Entra ID に**課の属性**があるか | 課レベルの動的グループが作れず、手運用になる | 人事側に課コード列の追加を依頼 | **高** |
| 3 | Entra ID **P1以上**を保有しているか | 動的グループが使えず、改編のたびに手作業になる | 保有状況を確認 | **高** |
| 4 | Notion の**契約プラン** | Form のファイル添付が使えるか不明。ゲスト上限・SAMLも変わる | 導入検討時にあわせて確認 | **高** |
| 5 | `02_限定_➀課` を**部メンバーに見せるか** | 権限マトリクスが確定しない | 原則は見せる。人事情報を扱う管理部のみ非表示 | 中 |
| 6 | 「**案件**」の定義と案件コードの採番 | 案件管理サイトが機能しない | 法人事業部主管で先に合意 | 中 |
| 7 | **業務委託者**はゲストか社内アカウントか | ビジネスパートナーサイトの外部共有設計が変わる | ゲスト推奨（棚卸ししやすい） | 中 |
| 8 | Teamsチャネルでの問合せを**残すか** | 導線ルールが確定しない | 残す。ただし依頼はFormへ代理起票 | 中 |
| 9 | **Teamsへの自動通知**が必須要件か | 必須ならNotion Formだけでは満たせない | 必須ならPower Automate Premium 1シートの検討に戻る | 中 |
| 10 | 旧サイトの**保持期間** | 移行判定ができない | 読み取り専用3か月 → アーカイブ | 低 |
| 11 | **Purview のライセンス**（E3/E5） | 秘密度ラベルの自動適用ができるか変わる | E3なら手動ラベル、E5なら自動ラベル | 低 |
| 12 | 「正本置き場」「案件管理」の**責任部署** | サイトのオーナーが決まらない | 下記の提案を参照 | 低 |

## 論点1: 新組織の課

本資料では仮に次の名称を置いています。**すべて仮です。**

| 部 | ➀課（仮） | ②課（仮） |
|---|---|---|
| 法人事業部 | ➀営業課 | ②カスタマーサクセス課 |
| スクール事業部 | ➀スクール運営課 | ②募集・マーケティング課 |
| 研修・講師統括部 | ➀講師管理課 | ②研修企画課 |
| デジタル開発部 | ➀サービス開発課 | ②社内IT課 |
| 管理部 | ➀総務・人事課 | ②経理課 |

課が3つ以上ある部、または課を置かない部がある場合は、ライブラリ構成が変わります。確定次第、A4の各ページを修正してください。

## 論点6: 「案件」の定義（提案）

- **案件 = 顧客と金銭のやりとりが発生する（または見込まれる）活動の単位**
- 案件コード = `YYYY-事業部コード-連番`（例: `2026-D01-0042`）
- このコードを **Notionの案件DB / SharePointのフォルダ名 / 見積・請求** で共通のキーにする

法人案件・スクール案件・研修案件で粒度が違うまま器だけ作ると、必ず形骸化します。**着手前に全社で1つに合意してください。**

## 論点12: 未定サイトの責任部署（提案）

### 正本置き場

| 役割 | 担当 |
|---|---|
| 運用管理者（版の差し替え、見直し期限の督促、アクセス権） | **管理部** |
| 内容オーナー（中身が正しいことへの責任） | **各規程の所管部署** |

文書管理は「置き場の管理」と「中身の責任」を分けないと機能しません。

### 案件管理

| 役割 | 担当 |
|---|---|
| 主管（案件定義、運用ルール） | **法人事業部** |
| 仕組み担当（ライブラリ構成、メタデータ、自動化） | **デジタル開発部** |

## この資料が置いている前提

以下は確認できていないため、前提として設計しています。**違っていた場合は該当箇所の修正が必要です。**

| # | 前提 | 影響範囲 |
|---|---|---|
| P1 | 全社員が Microsoft 365 のライセンスを保有 | 全体 |
| P2 | Entra ID に `department`（部）が人事データから同期されている | 権限設計 |
| P3 | Entra ID P1 以上を保有（動的グループが使える） | 権限設計 |
| P4 | Notion を全社員に導入する | 依頼受付の仕組み全体 |
| P5 | Power Automate は M365 Business プラン（**Premiumは購入しない**） | 依頼受付の実装方式 |
| P6 | 業務委託者は Entra ゲストユーザーとして招待する | ビジネスパートナーサイト |
| P7 | 各部の課は最大2〜3課 | ライブラリ数・グループ数 |

## この資料で作れなかったもの

**既存SharePointの実態調査は含まれていません。** 本資料は「新構成における各サイトの定義」であり、現在どのサイトに何があるかの棚卸し結果ではありません。

現行サイトの棚卸しは「B4 移行計画」の Phase 0 で、棚卸しシートを使って各部が実施してください。
