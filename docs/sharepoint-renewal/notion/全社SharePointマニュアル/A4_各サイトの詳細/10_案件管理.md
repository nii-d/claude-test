# 10 案件管理

## 1. 何のための場所か

**案件の成果物と経緯に、部署を越えてたどり着けるようにする場所。進捗管理はNotion、ここはファイルの置き場。**

## 2. 責任と読者

| 項目 | 内容 |
|---|---|
| 責任部署 | **法人事業部＝主管（案件定義・運用ルール）／デジタル開発部＝仕組み担当（ライブラリ構成・自動化）** |
| サイトオーナー | 法人事業部 1名／デジタル開発部 1名 |
| 想定読者 | 全社員（公開ライブラリ）／案件関係部署（限定ライブラリ） |
| 閲覧範囲 | 公開ライブラリは全社員、限定ライブラリは案件関係部署 |
| 秘密度ラベル | 社外秘 |
| URL | `/sites/wb-projects` |

> **このサイトを使い始める前に、「案件」の定義を全社で1つに合意してください。**
> 法人案件・スクール案件・研修案件で粒度が違うまま器だけ作ると、必ず形骸化します。
> 定義案と採番ルールは「B5 決めること一覧」に記載しています。

## 3. 書かれていること

| ページ | 中身 |
|---|---|
| ホーム | 案件管理の使い方、案件コードの採番ルール、**問い合わせボタン**、Notion案件ビューへのリンク |
| 案件コードの付け方 | 採番ルールと、既存コードの検索方法 |
| 案件の始め方・終わり方 | 案件開始時に作るもの、完了時に整理するもの |

## 4. 置かれているもの

| ライブラリ | 誰が見られるか | 誰が編集できるか | 中身 |
|---|---|---|---|
| `01_公開_案件成果物` | 全社員 | 案件関係部署 | 納品物、提案書、事例化した資料 |
| `02_限定_案件作業` | 案件関係部署のみ | 案件関係部署 | 見積・原価、顧客とのやりとり、作業中ファイル |

### フォルダの決まり

- **フォルダは案件コードの1階層のみ。** 年度で分ける場合でも `年度 / 案件コード` の2階層まで。
- 案件コードの形式: `YYYY-事業部コード-連番`（例: `2026-D01-0042`）
- **この案件コードを、SharePointのフォルダ名・Notionの案件DB・見積・請求で共通のキーにします。** これがないと横断できません。

### 必須の列（メタデータ）

| 列名 | 用途 |
|---|---|
| 案件コード | 横断の共通キー |
| 顧客名 | 検索用 |
| 主管部署 | 責任の所在 |
| 案件ステータス | 提案中／受注／進行中／完了／失注 |
| 受注日 / 完了日 | 期間の把握 |

## 5. 置かないもの

| 置かないもの | 代わりにどこへ |
|---|---|
| タスクの期限と担当 | Notion の案件・タスクDB |
| 日々の連絡 | Teams |
| 契約書の**ひな形** | 正本置き場 |
| 顧客の個人情報を含む名簿 | 限定ライブラリのみ。公開ライブラリには置かない |
| 部署内で完結する資料 | 各部サイト |

## 6. 問合せ窓口

| 用件 | 行き先 |
|---|---|
| 案件コードの採番・確認 | 依頼Form（宛先＝法人事業部・種別＝案件管理） |
| ライブラリ構成・権限の変更 | 依頼Form（宛先＝デジタル開発部） |
| 相談 | Teams「#案件管理」 |

## 7. 更新ルール

| 対象 | 誰が | いつ |
|---|---|---|
| 案件フォルダの作成 | 主管部署 | 案件開始時 |
| 案件完了時の整理 | 主管部署 | 完了後2週間以内（成果物を公開ライブラリへ移す） |
| 運用ルール | 法人事業部 | 半期ごと |
| 完了案件の棚卸し | 法人事業部 | 年1回（4月） |
