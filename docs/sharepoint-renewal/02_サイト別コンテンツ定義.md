# サイト別コンテンツ定義（何を書くか／何を置くか）

「何を置くか」より **「何を置かないか」** を決めるほうが効きます。置かないものリストが無いサイトは必ず物置になります。

---

## 1. サイトカルテ（全サイト共通テンプレート）

新規サイト作成時・年1回の棚卸し時に、各部が必ず記入するもの。
**このカルテを SharePoint リストに1サイト＝1行で登録し、全社マニュアルから自動表示させます**（→ `04_移行計画と全社マニュアル.md`）。Word で個別に作ると更新されません。

| 項目 | 記入内容 |
|---|---|
| サイト名 / URL | |
| 目的（1文） | 「〜のために〜を置く場所」 |
| 責任部署 | |
| サイトオーナー | 2名以上（氏名・役割） |
| 想定読者 | 全社員／部内／課内／業務委託者 |
| 秘密度ラベル | 社内限定／社外秘／関係者外秘 |
| **置くもの** | 3〜7個の箇条書き |
| **置かないもの** | 3個以上。「代わりにどこへ置くか」もセットで書く |
| ライブラリ構成 | ライブラリ名と権限 |
| 主要ページ | ページ名と用途 |
| 命名・フォルダ規則 | 第1階層の軸（年度／カテゴリ） |
| 保持・見直し | 保持期間、見直し頻度 |
| 問合せ窓口 | 依頼 Forms のリンク／Teams チャネル／FAQ |
| 最終更新日 | |

## 2. 部サイトの標準構成（法人事業部・スクール事業部・研修/講師統括部・デジタル開発部・管理部の5サイト共通）

**5部すべてでページ名・ライブラリ名・並び順を完全に揃えます。** 「あの部だけ作りが違う」は、全社マニュアルを作れなくする最大の要因です。

### 2.1 ページ構成

| ページ | 用途 | 必ず書く内容 |
|---|---|---|
| **ホーム（部TOP）** | 部の顔。全社員が最初に来る | ①部のミッション（3行）②業務範囲＝**何を引き受け、何を引き受けないか** ③体制図（課・人数・課長）④**問合せブロック（全部署共通レイアウト）** ⑤主要ドキュメントへのクイックリンク ⑥新着（お知らせ Web パーツ） |
| **➀課ページ** | 課の運営情報 | 課の役割／担当業務一覧／主要メンバーと担当領域／定例会の日時／課への依頼窓口／よくある依頼と標準リードタイム |
| **②課ページ** | 同上 | 同上 |
| **業務マニュアル案内** | 手順書の入口 | 手順書の一覧（リンク集）。手順書の実体は knowledge に置き、ここはリンクだけ |
| **FAQ** | 問合せを減らす | 過去の依頼から頻出Top10。Notion の依頼DBを四半期ごとに見て更新する |

> 元案の「【公開ドキュメント】TOP」ページは**ホーム内のセクションで足ります**。ページを6枚作ると、更新されないページが5枚できます。

### 2.2 ライブラリ構成（全部署共通）

| ライブラリ | 権限 | 置くもの | 置かないもの |
|---|---|---|---|
| `01_公開_共通` | 全社員 閲覧 | 部の業務フロー図、全社向け依頼テンプレート、部が発信する報告書・実績資料、対外資料の社内共有版 | 進行中の下書き（→OneDrive）、個人情報 |
| `01_公開_➀課` | 全社員 閲覧 | 課の成果物のうち全社に見せてよいもの、課が提供するサービスの説明資料 | 顧客個社の機微情報 |
| `01_公開_②課` | 全社員 閲覧 | 同上 | 同上 |
| `02_限定_部` | 部メンバー 編集 | 部内の会議資料、予算・実績の内訳、人員計画（機微でないもの）、他部と調整中の資料 | 人事評価（→管理部限定）、個人の作業メモ（→OneDrive） |
| `02_限定_➀課` | 課メンバー 編集 | 課の作業ファイル、顧客個社ごとの資料、見積・原価の作業版 | 確定した正本（→正本置き場） |
| `02_限定_②課` | 課メンバー 編集 | 同上 | 同上 |

**全部署共通の「置かないもの」（重要）**
- 個人の作業中ファイル → **OneDrive**
- 会話・相談 → **Teams**
- タスク・進捗管理 → **Notion**
- 規程・帳票の**最新確定版** → **正本置き場**（部サイトには置かない。置くとどれが最新か分からなくなる）
- 全社共通の手順書・FAQ → **knowledge**

## 3. 各サイトの個別定義

### 3.1 WorkBase（ハブ / トップ）
- **目的**: 全社員の情報の入口。ここから3クリック以内で目的の情報に着く。
- **置くもの**
  - 全社お知らせ（社長室・管理部が発信）
  - **全社マニュアル**（→ `04_`）
  - 全部署サイトへのナビゲーション（ハブナビ）
  - **全社共通の依頼 Forms への入口**（1本）
  - 依頼の進捗ボード（Notion）へのリンク
  - 社内カレンダー（全社イベント）
  - よく使うシステムのリンク集（勤怠・経費・人事システム等）
- **置かないもの**: 部署固有のファイル（→各部サイト）、規程の実体（→正本置き場）
- **責任部署**: 管理部

### 3.2 knowledge（管理部）

**正本置き場との違いを最初に定義しないと、必ず両方に同じ物が置かれます。**

| | knowledge | 正本置き場 |
|---|---|---|
| 性質 | **使い方・解説・ノウハウ** | **原本・確定版** |
| 例 | 「経費精算のやり方」「Teams の使い方」「用語集」 | 「経費規程 第4版」「経費精算書 様式」 |
| 更新 | 誰でも改善提案可 | 承認プロセス必須 |
| 形式 | 主に **SharePoint ページ**（検索しやすい） | 主に **ファイル**（版管理） |

- **置くもの**
  - 全社共通の業務マニュアル（ページ形式）
  - 社内用語集・略語集
  - IT・ツールの使い方（M365 / Notion / 各種SaaS）
  - オンボーディング資料（新入社員・中途入社が最初に読むもの）
  - 社内制度の解説（規程の「読み方」。規程本体は正本置き場へリンク）
  - ナレッジ記事（事例・失敗事例・Tips）
- **置かないもの**: 規程・様式の原本、部署限定の情報、進行中の案件情報
- **権限**: 全社員 閲覧／全社員 ページ投稿可（承認は管理部）
- **記事テンプレート**: 目的 → 対象者 → 手順 → よくあるつまずき → 問合せ先 → 最終更新日・オーナー
- **鉄則**: 全記事に **オーナーと見直し期限** を必須にする。無いと1年で信用されなくなります。

### 3.3 社長室
- **目的**: 経営の意思と全社方針の発信。
- **ライブラリ**
  - `01_公開_共通`（全社員 閲覧）: 経営方針、中期経営計画、全社通達、社長メッセージ、月次の全社共有資料
  - `02_限定_部`（社長室メンバーのみ）: 取締役会・経営会議の資料と議事録、M&A/資本政策、個別の人事案件
- **注意**: `02_限定_部` は**部メンバーにも見せない前提**（3.5 の課限定より厳しい）。秘密度ラベルは「社外秘」だが、実質は限定共有。ここだけ別途、閲覧者を明示的に限定してください。
- **置かないもの**: 部門の実務資料

### 3.4 正本置き場
- **目的**: 「これが最新で正しい」と全社が信じられる唯一の場所。
- **責任**: 管理部＝運用管理者／各規程の内容オーナー＝各部
- **ライブラリ**

| ライブラリ | 権限 | 中身 |
|---|---|---|
| `01_規程・規則` | 全社員 **閲覧のみ**（編集は管理部） | 就業規則、各種規程、細則 |
| `02_様式・帳票` | 全社員 **閲覧のみ** | 申請書、報告書テンプレート、契約書ひな形 |
| `03_全社マニュアル` | 全社員 **閲覧のみ** | 本プロジェクトの成果物含む |
| `04_改訂中` | 管理部＋内容オーナー 編集 | 承認前の改訂版 |

- **必須メタデータ**: 文書番号 / 版数 / 制定日 / 改訂日 / **内容オーナー** / **次回見直し期限** / 承認者
- **運用ルール**
  - 全社員は**閲覧のみ**。編集権を配ると正本でなくなります。
  - 改訂は `04_改訂中` で行い、承認後に管理部が正本ライブラリへ差し替える。
  - **バージョン履歴を有効化**し、旧版は削除せず履歴に残す。
  - `次回見直し期限` を過ぎた文書を一覧するビューを作り、管理部が月次で督促する。
- **置かないもの**: 下書き、部署の作業ファイル、規程の「解説」（→knowledge）

### 3.5 案件管理
- **目的**: 全社横断で案件の成果物と経緯にたどり着けるようにする。**進捗管理は Notion。SharePoint は成果物の置き場。**
- **着手前の必須合意**: 「案件」の定義。案として —
  - 案件 = **顧客と金銭のやりとりが発生する（または見込まれる）活動の単位**
  - 案件コード = `YYYY-<事業部コード>-<連番>` 例: `2026-D01-0042`
  - このコードを **Notion の案件DB / SharePoint のフォルダ名 / 見積・請求 で共通キー**にする（これが無いと横断できません）
- **ライブラリ**

| ライブラリ | 権限 | 中身 |
|---|---|---|
| `01_公開_案件成果物` | 全社員 閲覧 | 納品物、提案書、事例化した資料。**案件コードのフォルダ**で管理 |
| `02_限定_案件作業` | 案件関係部署 編集 | 見積・原価、顧客とのやりとり、作業中ファイル |

- **メタデータ列**: 案件コード / 顧客名 / 主管部署 / 案件ステータス / 受注日 / 完了日
- **置かないもの**: タスクの期限と担当（→Notion）、日々の連絡（→Teams）
- **注意**: フォルダ階層は `案件コード` の1階層のみ。年度別にするなら年度→案件コードの2階層まで。

### 3.6 ビジネスパートナー（関係者外秘 / スクール事業部）
- **目的**: 業務委託者（講師等）に必要な情報だけを渡す。
- **設計上の最重要点**
  - **WorkBase ハブに関連付けない。** ハブナビには社外秘サイトのリンクが並ぶため、ゲストに見えると事故になります（リンク先は開けなくても、サイト名の一覧＝組織の内部構造が漏れます）。
  - サイト単位で外部共有を許可。**テナント既定は「既存ゲストのみ」に絞る。**
  - 秘密度ラベル「関係者外秘」を適用し、ダウンロード制限（制限付き Web のみ）を検討。
  - ゲストは `SG-BP-Partners` グループ経由で追加。個人を直接追加しない。
  - **四半期ごとにゲストアクセスレビュー**（契約終了者が残るのが最大のリスク）。
- **ライブラリ**

| ライブラリ | 権限 | 中身 |
|---|---|---|
| `01_パートナー共有` | 社員＋ゲスト 閲覧 | 業務手順書、教材、スケジュール、様式（請求書ひな形等）、連絡先 |
| `02_パートナー提出` | 社員＋ゲスト 編集 | 業務委託者からの提出物（報告書等） |
| `03_社内限定` | 社員のみ | 委託者の評価、単価・契約情報 |

- **ページ**: パートナー向けTOP（はじめに読む／今月のお知らせ／問合せ先／FAQ）
- **置かないもの**: 他社パートナーの情報（相互に見えます）、社員の人事情報、単価表
- **重要**: `03_社内限定` を同一サイトに置くのはリスクです。**単価・契約情報は管理部サイトに置き、BP サイトには一切置かない**方を推奨します。

## 4. サイトカルテ記入例（法人事業部）

そのままコピーして各部に配ってください。

```
サイト名 / URL : 法人事業部 / /sites/wb-div01
目的           : 法人向け事業の推進に必要な情報と成果物を集約し、他部署が
                 法人事業部に何を依頼できるかを明確にする場所
責任部署       : 法人事業部
サイトオーナー : ●●（部長・最終責任）／▲▲（運用担当）
想定読者       : 全社員（公開ライブラリ）／部員（限定ライブラリ）
秘密度ラベル   : 社外秘
置くもの       : ・法人向けサービスの説明資料
                 ・提案書・見積書のテンプレート
                 ・受注/失注の振り返り資料
                 ・部の業務フロー図と依頼受付ルール
                 ・部内会議資料（限定）
                 ・顧客個社ごとの作業ファイル（課限定）
置かないもの   : ・進行中のタスクと期限     → Notion 依頼DB
                 ・顧客とのやりとり         → Teams
                 ・契約書の正本             → 正本置き場
                 ・個人の作業メモ           → OneDrive
                 ・全社共通の手順書         → knowledge
ライブラリ構成 : 01_公開_共通（全社閲覧）/ 01_公開_➀課 / 01_公開_②課
                 02_限定_部（部編集）/ 02_限定_➀課 / 02_限定_②課
主要ページ     : ホーム / ➀課 / ②課 / 業務マニュアル案内 / FAQ
フォルダ規則   : 第1階層＝年度（2階層まで）
保持・見直し   : 提案書5年 / 会議資料3年 / 年1回（4月）棚卸し
問合せ窓口     : 全社依頼Forms（宛先=法人事業部）/ Teams「#法人事業部-相談」
最終更新日     : 2026-04-01
```
