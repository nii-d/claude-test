# Notion 案件管理 運用ルール

> 社内周知用。**仕組みより運用が9割**。ルールが守られなければ、どれだけ良いDBを作っても Word/OneNote 時代に戻る。

---

## 大原則

> **「案件のことを知りたければ Notion を開けば分かる」状態を全員で維持する。**

---

## 1. 議事録のルール

| # | ルール | 理由 |
|---|---|---|
| 1-1 | **議事録は Notion に直接書く。Word / OneNote で新規作成しない** | 散在の再発防止。例外を1つ認めると崩れる |
| 1-2 | **会議中に打ち込む。清書工程を作らない** | 「後で清書」は9割書かれない |
| 1-3 | 会議終了時に「決定事項」を読み上げて確認する | その場で認識ズレを潰せる。書く精度も上がる |
| 1-4 | タイトルは `YYYY-MM-DD_相手先_目的` で統一 | 検索とソートが効く |
| 1-5 | 必ず `案件` プロパティを設定する（社内MTGも） | 未設定だと案件ページに現れず、存在しないのと同じになる |
| 1-6 | 案件に紐づかない会議（全社会議など）は `案件` を空欄にしてよい | |
| 1-7 | 議事録は**その日のうちに**公開する。書きかけでも共有する | |

## 2. タスクのルール

| # | ルール | 理由 |
|---|---|---|
| 2-1 | **会議中に出たToDoは、その場でタスクDBに登録する** | 議事録に書くだけでは実行されない |
| 2-2 | タスクには必ず `担当者` と `期限` を入れる | どちらか欠けたタスクは実行されない |
| 2-3 | 完了したら `完了フラグ` にチェックを入れる | 案件DBの「未完了タスク数」がこれで動く |
| 2-4 | 期限が変わったら期限を書き換える。放置しない | 期限切れビューが機能しなくなる |

## 3. 案件のルール

| # | ルール | 理由 |
|---|---|---|
| 3-1 | **ステータスを変えたら「現状サマリー」も必ず更新する** | ここが古いと仕組み全体の信頼が失われる |
| 3-2 | 「現状サマリー」は**その案件を全く知らない人向けに**書く | 社内用語・略語を避ける |
| 3-3 | 案件名は `クライアント名_研修名_実施年月` で統一 | |
| 3-4 | 「次のアクション」は常に1つ以上埋まっている状態にする | 空＝止まっている案件、と判断できるようにする |
| 3-5 | 失注しても削除しない。`失注` ステータスにして理由を残す | 失注理由の蓄積が次の提案の武器になる |

## 4. ファイルのルール

| # | ルール | 理由 |
|---|---|---|
| 4-1 | **ファイルの正本は SharePoint。Notion にはリンクのみ置く** | 二重管理は必ず事故を起こす |
| 4-2 | 案件ごとに SharePoint のドキュメントセットを作り、URLを案件DBに登録する | |
| 4-3 | Notion にファイルを直接アップロードしない（一時的なメモ画像を除く） | Word/OneNote 問題の再生産を防ぐ |
| 4-4 | 「あのスライドどこ？」は SharePoint 検索、「あの話どこ？」は Notion 検索 | 使い分けを周知する |

## 5. 権限のルール

| # | ルール | 理由 |
|---|---|---|
| 5-1 | 社員はメンバー、業務委託講師はゲスト（または SharePoint 権限のみ） | |
| 5-2 | 業務委託講師に案件ページ全体を共有しない。**「講師向け共有ページ」だけ**を共有する | 受注金額・社内議論の漏洩防止 |
| 5-3 | 契約終了時にゲストを削除する。四半期ごとにゲスト一覧を棚卸しする | 放置するとアクセス権が残り続ける |
| 5-4 | 受講者の氏名など個人情報は、必要最小限に留める | |

---

## 移行方針（導入時のみ）

| # | ルール |
|---|---|
| M-1 | **既存議事録を全部移行しない。** 進行中案件の直近1年分のみ |
| M-2 | 旧 Word / OneNote は「参照専用アーカイブ」として残し、**書き込みは禁止**にする |
| M-3 | 移行日を決め、その日以降の新規はすべて Notion とする |
| M-4 | 最初の1か月は「Notion に書いてある？」を口癖にして定着させる |

---

## 定例チェック（週次15分）

朝会または週次定例で、以下の3ビューを順に映して確認する。

1. **案件DB「要注意案件」** … 🔴 が立っている案件を潰す
2. **タスクDB「期限切れ」** … 期限を切り直すか、完了にする
3. **議事録DB「未決事項あり」** … 持ち帰りのまま止まっている論点を拾う

> この3つがゼロに近い状態を保てていれば、案件管理は健全に回っている。
